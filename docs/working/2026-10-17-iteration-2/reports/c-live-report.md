## Defects

1. (Low, accessibility) `frontend/suglist.js` item(): `aria-label` "Use X for this row" hides the generic and reason from assistive technology. Repro: open Spell it on Citrizene, read the accessibility snapshot: `button "Use Cetirizine for this row": "Cetirizine sounds like"`. Visible text is "Cetirizine / sounds like" (and a generic line when it differs). Same for the mic (`aria-label` "Say the name", visible "Say it").
2. (Low, layout) At 1024x768 (short viewport) a full page of 8 items with a generic line is about 736 px; the whole dialog scrolls and Close / Use this are below the fold when it opens. Repro: stub check-row to 40 options with generic names, open at 1024x768. Reachable by scrolling or Tab, but not visible.
3. (Low, copy) With more than 40 matches the label says "(60 found: type more letters to narrow them)", but typing in the field never narrows the list (one request per open, no search on input). Repro: stub total 60 with 40 options, type letters: no new list, no request. Either the hint or the behaviour should change.

## Concerns (not defects)

1. Brief step 2 expected the list to update while typing a misspelled name; the plan (line 24) designs one request per open, so it is not built. Owner may want a debounced re-check.
2. Mic stays enabled after the page becomes working or view-only while the dialog is open, and a tap then does nothing silently (it is disabled on the next redraw). Unlikely in real use because the dialog cannot open in those states.
3. Unsupported browser: mic is visible and enabled, the reason shows only after a tap. The brief asked for hidden or disabled with a reason.
4. Opening the dialog while working does nothing and says nothing (the Spell it button is not disabled while working).
5. Prednisolone chosen via Use this on a row that had empty instructions now shows "[unverified: confirm with doctor]" in Instructions, although the doctor confirmed the name. It comes from check-row's returned instructions marker (behaviour from before I2-c); it would print.
6. Upload error text shows the raw status and server word: "The server answered 500 (boom)".
7. Tests not possible here: dose-check row (no dosing data), real microphone and Safari mp4.
