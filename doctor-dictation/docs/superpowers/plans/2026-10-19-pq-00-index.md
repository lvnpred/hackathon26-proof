## Shared contract (all plans use these names)

### Prescription row (`structured.rx[i]`)

| Field | Values | Owner plan |
|---|---|---|
| `generic_source` | `""` (none), `"lexicon"` (exact match), `"doctor"` (typed, dictated or accepted) | a defines `""`/`"lexicon"`; g adds `"doctor"` |
| `generic_suggestion` | AI-suggested composition, `""` when none. Never printed, never learned | g |
| `combo_base` | base brand ("Zerodol") when the name is a known brand + combination suffix; the page's "Add generic" signal. Filled by `surface.generic_fields` with `generic` and `generic_source` | a |
| `generic_suggestion_unknown` | list of suggestion components that are not a known canonical (drives amber) | g |
| `generic_pending` | bool; a doctor generic not yet confirmed blocks Save; removed at save | g |

Plan g adds an explicit correction patch whitelist, `patch_generics` (today the row dict in `rowcheck.py:68-75` acts
as one). A doctor generic is learned into the clinic overlay (plan f), not `clinic_formulary`.

Rule (g): when `generic_source == "doctor"`, no server path recalculates `generic` (`RECOMPUTED_ROW_FIELDS`,
`preserve_untouched_rx_status`, `rowcheck`).

### Lookup functions (plan a)

- `doctor_dictation/core/determinism.py: _exact_lookup(name: str) -> str` — canonical only on an exact alias/brand
  match (space and hyphen count as the same: "Moxikind CV" = "Moxikind-CV"), else `""`. The generic and
  `formulary.learnable` use this. `_canonical_lookup` (fuzzy) stays for name
  suggestions only.
- `doctor_dictation/core/combo.py: combo_suffix(name: str) -> tuple[str, str] | None` — `(base brand, suffix)` when the
  name is a known brand plus a combination suffix (-P, -D, -GP, -AV, -CV, -XT, -LC, -AM, -H, Plus, Forte, MR, SR, …),
  else `None`.

### Clinic overlay (plan f)

- Migration `doctor_dictation/db/migrations/010_clinic_overlay.sql`, table `clinic_overlay`:
  `id, kind ('medicine'|'investigation'), entry_key (casefolded name), action ('add'|'edit'|'hide'), data (JSON text),
  base_sha (sha256 of the shipped entry when edited; for an add, '' or the `claimant_sha` of the shipped entry that
  claimed the name, which raises `shipped-changed` when that entry later changes), source ('doctor'|'admin'|'learned'), created_by,
  created_at, updated_at, removed_at`, `UNIQUE(kind, entry_key)`.
- `doctor_dictation/db/overlay.py`: `upsert(conn, kind, entry_key, action, data: dict, base_sha, source, user_id) -> int`,
  `list_rows(conn, kind) -> list[dict]`, `reset(conn, kind, entry_key) -> bool`.
- `doctor_dictation/core/overlay.py`: `effective_entries(kind, shipped: list[dict], rows: list[dict]) -> tuple[list[dict], list[dict]]`
  returns `(entries, flags)`; a flag is `{"entry_key", "reason": "shipped-changed" | "safety-override"}`.
- Medicine overlay `data` minimum: `{"name": str, "generic": str}`; an `add` becomes an entry
  `{"canonical": generic, "brands": [name], "aliases": [], "forms": [], "strengths": [], "clinic": true}`.
- Under an active clinic overlay, `determinism.load_lexicon()` returns the effective medicine entries, so plans a and g
  need no overlay-specific code. Activation follows the existing pattern (`api/formulary.py: use_clinic_layer`, a ContextVar).
- A shipped entry may carry `"safety": true`: the shipped entry wins over a clinic edit, with a `safety-override` flag.
- `clinic_formulary` (migration 009) stays the learned-name counter (2 confirmations) for names nobody typed a generic for.
- App-admin review/export: owner-only screen (env `OWNER_USERNAMES`, comma-separated usernames); edits export as a JSON
  file `{"kind": "medicine"|"investigation", "changes": [{"action", "entry_key", "data"}]}`; operator command
  `python -m doctor_dictation.admin apply-list-changes <file>` folds it into the shipped JSON in the repo (then commit + deploy).

Additions from plan f (written 2026-10-19): `core/overlay.py` also has `entry_sha`, `validate_data`, `OverlayState`,
`activate`/`active`, `register_shipped`/`shipped`, `screen_rows`, and **`effective_view(kind, shipped)`**, the hook plan
h's investigations loader calls; `determinism.py` gains `shipped_lexicon()` and `lexicon_identity()`; the `/api/format`
cache key includes the overlay version. `source`: `admin` = clinic list screen, `doctor` = from a prescription,
`learned` reserved. A medicine `add` needs a generic. `apply-list-changes` is a dry run without `--confirm`; the export
supports `add` and `edit` only, and an owner `edit` never changes `canonical`.

Additions from plan f's final fix wave (2026-10-20): every name the overlay removes (a hidden entry's names, brands or
aliases an edit drops) is **blocked** for that clinic. A blocked name stays as dictated and grades unknown-medicine.
It is never fuzzy-routed, suggested, offered to the AI repair prompt, or counted as heard inside a longer word
(`core/drugnames.py`: `is_blocked`, `without_blocked`; `core/candidates.py` scorers take `guard`, and only
`formulary._twin` passes `guard=False`). A rename always keeps the old canonical as an alias. `correct_drugs` and the
name helpers moved to `core/drugnames.py` and are re-exported from `determinism`. Screen items carry `flag_reason` when a
deploy sets a clinic row aside (flag `shipped-changed`). `record_confirmation` commits: call it after your own commit.
Plans g and h: any new path that maps a name to a drug must respect the blocked set.

### Learning threshold (owner rule, 2026-10-19; plans f, g, h)

- `clinic_overlay` gains `confirm_count INTEGER NOT NULL DEFAULT 0`; new table
  `clinic_overlay_docs(overlay_id, document_id, PRIMARY KEY(overlay_id, document_id))` so a re-save never counts twice
  (same pattern as `clinic_formulary_docs`, migration 009).
- A row is **active** when `removed_at IS NULL AND (source = 'admin' OR confirm_count >= formulary.THRESHOLD)`
  (`THRESHOLD = 2`, `core/formulary.py`; one constant for medicines and investigations). Only active rows reach
  `effective_entries`.
- `db/overlay.py: record_confirmation(conn, kind, entry_key, action, data: dict, base_sha, document_id, user_id) -> int`
  (returns the count; source `'doctor'`). If `data` differs from the stored pending data, the row takes the new data
  and the count restarts at 1 (its docs ledger is cleared). `upsert` stays for admin edits (live at once).
- `db/overlay.py: approve(conn, kind, entry_key, user_id) -> bool` — the list screen's "Approve now" (sets source
  `'admin'`), audited. Pending rows appear on the list screen as "Pending (n of 2)".
- `DocumentCreate` gets `remember_generics: list[int]` (plan g, Q20: overriding a SHIPPED generic counts only when
  ticked; an unknown brand's confirmed doctor generic counts without a tick).
- Plan g (doctor generic) and plan h ("Remember for this clinic") call `record_confirmation` on save, never `upsert`.
  The prescription itself always prints what the doctor entered.
- As built by plan g (2026-10-20), and the pattern plan h follows for `remember_investigations`:
  - a learned row is action `add`, keyed `formulary.key(name)`, never `edit`; overriding a shipped brand sets
    `base_sha = overlay.claimant_sha(...)`;
  - learning runs after the document commit, reads the raw request rows (indexes match the page's kept-row order), and
    pre-checks `overlay.conflicts`; a refused row is logged and skipped;
  - a blocked name is never learned, and neither is a generic (or any of its components) that is blocked;
  - when an admin row owns the key (`record_confirmation` returns 0), no audit row is written;
  - a shipped item counts only when ticked.
- A model-returned value (generic, test) becomes the doctor's only when the doctor said it in that correction;
  echoes of the current or listed value are dropped.

### Investigations (plan h)

- Shipped catalogue `doctor_dictation/core/lexicon/investigations.json`:
  `{"version", "entries": [{"canonical", "aliases": [], "category", "print", "safety"?}]}`.
- Item shape `structured.investigations[i] = {"text", "canonical", "status", "source"}`; status `"verified"` | `"new"` |
  `"not-dictated"` | `""` (legacy string, unchecked); source `"dictated"` | `"doctor"`. A plain string still loads.
- Printed text: `text`, plus ` (canonical)` when the two differ case-insensitively; unknown tests print `text`.
  Function `doctor_dictation/core/investigations.py: print_text(item) -> str` (plan h); plan e's inline list accepts a
  string or an item and calls `print_text` for items.
- `"not-dictated"` items block Save (409, like `screen_unverified`) until the doctor keeps (source becomes `"doctor"`)
  or removes them; `"new"` warns only.

Additions from plan h (written 2026-10-19): a Save 409 adds `investigations_block: [{index, text}]` (`block` always
present; `error` "investigations not dictated" when only tests block); `DocumentCreate` gets
`remember_investigations: list[int]` (beside plan g's `remember_generics: list[int]`, above); endpoint `POST /api/v1/investigations/lookup`; `core/investigations.py` has `key`,
`entries`/`activate`, `lookup`, `coerce_items`, `check_items`, `reconcile`, `regrade`, `screen`, `remember_row`,
`flatten`; `prose.py` gets `heard_pool`/`missing_in_pool` (plan g's `heard_words`/`missing_words` stay as they are); `fallback._is_demo` becomes `is_demo`. As built
(2026-10-20): investigation overlay rows are keyed by `overlay.entry_key_of` (`formulary.key`, as for medicines); an
`add` carries `data.name` (its canonical), an `edit` carries only `aliases`; lookup indexes effective entries by
`investigations.key` and is the only reader. `core/investigations.py` also has `lookup_in`, `clinic_entries`, `heard`;
`api/investigations.py` has `remember_from_save` (plan g's learning pattern, plus a `_goes_live` simulation through the
real read path). Investigation names follow their own rule (`overlay_validate._ix_name`: 2-60 characters, at most 8
words, `[A-Za-z0-9][A-Za-z0-9 .'+/&-]*`, at least one letter; medicines keep `formulary.clean_name`). Twin, hidden and
"already listed" checks for investigations compare by `investigations.key` and its spaceless form as well as `_claim`.
Investigation dicts survive `validate_structured`; `/api/format` caches them unchecked and checks each answer.

### Correction response (plan c)

- `/api/v1/correct` response adds `changed_rows: list[int]` (indexes into the returned `rx`); the page clears
  confirmations only for those rows.

### Vitals (plan d)

- `structured.vitals = {"bp", "pulse", "weight", "spo2", "temp"}`, strings, `""` when not dictated. Plan e prints it
  once under the patient line.

## Shared rules for every plan

- Files stay under 500 lines; `frontend/app.js` is already over: put new page code in new modules.
- Tests: `.venv/bin/python -m pytest`; the autouse `DB_PATH` temp fixture in `tests/conftest.py` keeps the dev DB safe.
- No commit without the owner's word; plan steps say "commit" but the executor asks first.
- Cache-busting `?v=` pins on changed static files must be bumped (tests assert them).
